    <Heading as="h2" variant="heading-strong-l">Batch Analysis and Streaming Architecture</Heading>
    <Text variant="body-default-m" onBackground="neutral-medium">
      The repository pairs CSV-based historical analysis with a streaming prototype built around Kafka, Spark Structured Streaming, and Cassandra. Separate ingestion, fusion, and storage components make the data flow inspectable while preserving the existing analysis workflow.
    </Text>
    <ul style={{ paddingLeft: '1.25rem', display: 'flex', flexDirection: 'column', gap: '0.5rem' }}>
      <li style={{ listStyleType: 'disc' }}>
        <Text variant="body-default-m" onBackground="neutral-strong">
          <Text as="span" variant="body-strong-m">Source-specific ingestion:</Text> Separate Kafka topics carry Garmin measurements, weather observations, and RouterSense download metadata. Explicit Spark schemas keep each event format visible at the fusion boundary.
        </Text>
      </li>
      <li style={{ listStyleType: 'disc' }}>
        <Text variant="body-default-m" onBackground="neutral-strong">
          <Text as="span" variant="body-strong-m">Time-based fusion:</Text> The Spark job parses timestamps and defines left joins with two-hour watermarks. Its RouterSense input represents hourly download metadata, keeping that granularity distinct from the underlying network records used in batch analysis.
        </Text>
      </li>
      <li style={{ listStyleType: 'disc' }}>
        <Text variant="body-default-m" onBackground="neutral-strong">
          <Text as="span" variant="body-strong-m">Storage design:</Text> The job configures CSV and Cassandra outputs with separate checkpoint locations. Cassandra tables partition measurements by device and day, then order records by timestamp.
        </Text>
      </li>
    </ul>
